partifactory is a self-hosted place for the pages, tools, docs and small apps a household and its AI agents make. Each one is a part: it gets its own sandboxed host, a name that means something, and every version kept forever.

01 · The idea

One part, one host, one link

Chat agents make useful things all day: a packing list, a chore chart, a dashboard, a little game. Usually they vanish into a transcript. partifactory gives each one a permanent address, so the link an agent posts in chat keeps working, keeps improving, and keeps asking who's allowed in.

VERSIONS

Nothing is ever lost

Every save is an immutable version: a manifest of content hashes. A one-line edit to a forty-file part stores one new blob. Restore any version; deleted parts sit in a 30-day bin.

KINDS

Whatever the agent wrote

HTML pages, Markdown docs, plain text and prebuilt bundles, with React and TSX next. CDN script tags are mirrored at build time, so a part never loads anything from a third party when it runs.

GRANTS

Every view is a decision

Parts start private to their maker. Share with people, groups or the whole household; only the admin can make a link that leaves the house, like the one you used to get here.

02 · Safety

Agent-written code, kept in its drawer

Code from an agent is untrusted by default. Every part runs the way Claude's own artifacts do: in a sandboxed document with an opaque origin. It can't read cookies, can't reach other parts, and can only fetch its own files.

CAPABILITIES

Access lives in the path

A signed, host-bound token in the URL carries each decided grant, so serving a file needs no database lookup. Revoking access bumps an epoch and takes effect at once.

NO COOKIES

Part hosts never see one

Sessions live only on the workspace host. A part can't steal them, can't toss cookies onto the domain, and can't script its wrapper.

SAFE DEFAULTS

Set up once, left alone

Secure headers, rate limits, quotas, nightly exports and a cap on every store that grows are all on by default. Turning one off takes an explicit [unsafe] key.

03 · Agents

Any AI can find it and use it

Tell an agent nothing but the address, and it can discover everything else. The same operations are offered over MCP, an HTTPS JSON API, a part CLI and a skill file, and every agent connects with its own scoped, revocable identity.

04 · Shared data

Pages that remember, and update live

A part's page gets window.storage, the same API Claude's artifacts use, with personal and shared data. When anyone else writes, every open copy hears about it within a second, so a chore chart, a guestbook or a multiplayer game needs no backend at all.

// save for everyone, then hear everyone else
await window.storage.set("px:3:4", "#e4572e", true);

window.partifactory.on("data.changed", async e => {
  const r = await window.storage.get(e.key, true);
  paint(e.key, r && r.value);
});
TRY IT

Bloom, a garden war with no server

Every player's seeds are one shared key. Each browser replays the same moves through the same deterministic simulation, so the board needs no game server: partifactory's live data events carry the move log between players. Snapshots of shared data are on by default, so a vandal's work is one tap to undo.

05 · Built like an appliance

One binary, one folder

RUST

A single static binary

Every asset embedded, served from a ~20 MB image. Builds run in a child process, so a compiler panic costs one build, not the server.

/data

Back up one folder

SQLite in WAL mode plus content-addressed blobs. A nightly export is portable to any host, and imports bump an epoch so old access can't come back.

PORTABLE

No vendor lock-in

Any OIDC provider, any reverse proxy, any CI or none. The first deployment's tunnel and identity provider are adapters behind config.
